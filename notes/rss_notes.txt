
RSS NOTES
=========


Bus addressing and data
-----------------------

A bus usually uses an address AND data:

- Handler:

  [READ BUS/n aaaa] BUS/n = XYZ/n(a).
  [WRITE BUS/n aaaa] XYZ/n(a) = BUS/n.

- Invocation:

  XYZ/n = BUS/n(ADDR).
  BUS/n(ADDR) = XYZ/n.

A bus may omit the address or the data (or both).

No address but data:

- Handler:

  [READ BUS/n] BUS/n = XYZ/n.
  [WRITE BUS/n] XYZ/n = BUS/n.

- Invocation:

  XYZ/n = BUS/n.
  BUS/n = XYZ/n.

No data but address:

- Handler:

  [BUS aaaa] SRC_ADDR/4 = a.

- Invocation:

  BUS(ADDR).

No address and no data:

- Handler:

  [BUS] EVENT_COUNT/32 += 1.

- Invocation:

  BUS.


Prefixes
--------

Prefixes are considered modifiers of instructions which must be present before
the actual opcode is fetched.

The following cases of prefix handling should be considered:
- Multiple occurrences of the same prefix (allow / disallow)
- Order of multiple different prefix (allow / disallow)
- mutually exclusive different prefixes (invalid, use first, use last)


Extensions
----------

Consider class-like extension of components (however, rather macro processing
than OOP). Initialization section is always incremental, replacement of
handlers must match handler specification exactly (otherwise, an additional
handler is added), for example:


CPU CPU_1(BUS_1/8, ATTR_1 = 0)
{
    VAR VAR_1/8.

[RESET]

    VAR_1/8 = UINT/8(ATTR_1).

    $FETCH(BUS_1/8, 16).

[FETCH 00000000]

    .  ; NOP

[FETCH 00000001]

    VAR_1/8 += 1.  ; increment VAR_1

[FETCH 00000010]

    BUS_1/8 = VAR_1/8.  ; send VAR_1 to BUS_1
}


CPU CPU_2 =CPU_1  ; extends CPU_1, adds bus BUS_2/8 and attribute ATTR_2
(
    BUS_2/8,
    ATTR_2 = 1
)
{
    VAR VAR_2/8.

RESET:

    ; replaces RESET handler of CPU_1

    =CPU_1  ; includes RESET handler of CPU_1

    $CLEAR.  ; clear all variables (including VAR_1/8)

[FETCH 00000010]

    ; replaces FETCH 00000010 handler of CPU_1

    =CPU_1  ; includes FETCH 00000010 handler of CPU_1

    VAR_2/8 += ATTR_2.  ; increment VAR_2

[FETCH 00000011]

    ; add a new FETCH handler

    BUS_2/8 = VAR_2/8.  ; send VAR_2 to BUS_2
}
